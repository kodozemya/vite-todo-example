# Приклад: Проєкт на Vite

Еталонний розв'язок бою з босом регіону **«Кузня Бандлів»** (Збірка та інструменти).
Той самий «Список справ», що й у [`example-js-todo`](../example-js-todo),
але зібраний Vite і розбитий на модулі.

Макет: [ToDo list](https://www.figma.com/design/33vXaYMe6v0WHUgSLqwFGB/ToDo-list?node-id=0-1)

> Це приклад, а не шаблон. Порівняй його з `example-js-todo` — саме різниця
> між ними і є змістом цього бою.

## Як запустити

```bash
npm install     # поставити залежності (одна: сам Vite)
npm run dev     # сервер розробки з миттєвим оновленням — http://localhost:5173
npm run build   # зібрати продакшн-версію у теку dist/
npm run preview # подивитися на зібране як на справжньому сервері
```

## Що змінилося порівняно з версією без збирача

| | `example-js-todo` | `example-vite-todo` |
| --- | --- | --- |
| Запуск | відкрити `index.html` | `npm install && npm run dev` |
| Код | один `app.js` | чотири модулі в `src/` |
| Стилі | `<link>` у розмітці | `import "./style.css"` у `main.js` |
| `<script>` у HTML | сам застосунок | лише точка входу `/src/main.js` |
| Продакшн | ті самі файли | `dist/` з мініфікацією й хешами в іменах |

## Структура

```
index.html          розмітка; єдиний <script> — точка входу
src/
  main.js           з'єднує модулі: елементи, підписки, події
  state.js          список справ і єдиний спосіб його змінити
  storage.js        читання й запис у localStorage
  render.js         перетворення списку на розмітку
  style.css         стилі за макетом
```

Межі між модулями проведені не навмання, а за питанням
**«що зміниться, якщо…»**:

- Список поїде на сервер замість localStorage → зміниться **тільки** `storage.js`.
- Зміниться макет → **тільки** `render.js` і `style.css`.
- З'явиться фільтр «показати лише невиконані» → **тільки** `main.js`:
  він і так вирішує, що передати в `renderTasks`.

Якщо зміна вимоги зачіпає три файли з чотирьох — межі проведені неправильно.

Видалення справи — та сама перевірка вже на практиці. Порівняй із
`example-js-todo`: там воно розкидане по одному файлу разом з усім іншим,
тут — `deleteTask` у `state.js`, хрестик у `render.js`, підписка на клік
у `main.js`. Кожен файл отримав рівно свою частину і жодного рядка чужої.

## Три речі, на які дивиться ментор

**1. Модулі справді розділені, а не просто розкладені по файлах.**
`state.js` не імпортує `document`. `render.js` не імпортує `state.js` —
список приходить йому аргументом. Чотири файли, що всі імпортують одне одного,
це той самий один файл, тільки з чотирма вкладками.

**2. `node_modules` і `dist` немає в репозиторії.**
Обидві теки в `.gitignore`. `node_modules` відновлюється з `package-lock.json`
однією командою, `dist` — з вихідників. А от **`package-lock.json` комітиться
обов'язково**: без нього `npm install` у ментора може поставити інші версії,
ніж у тебе, і «в мене працює» стане правдою в буквальному сенсі.

**3. Стилі підключає JavaScript, а не `<link>`.**
`import "./style.css"` у `main.js` виглядає дивно, поки не подивишся у `dist/`:
Vite бачить стилі у графі імпортів, мініфікує їх і дає файлу ім'я з хешем
(`index-VUf1gMoO.css`). Хеш змінюється разом із вмістом, тому браузер
користувача ніколи не покаже старий кеш після оновлення сайту.
